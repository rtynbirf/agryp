# Тикет 004 · ./finish-хук юнита: чистота между смертью и рестартом

Роль: ЯДРО + ДОКТОР (контракт — AGENTS.md §3). Статус: open. Виток: 6.
Приоритет: высокий. ЦУ Хозяина (Виток 5): виток 6 открывается этим тикетом.

## Задача

s6-урок: у службы есть `finish`-скрипт, который исполняется после смерти
попытки и до cooldown — уборка за агентом до следующего входа:

- ключ `.agent`: `finish = <строка sh>` (по умолчанию пуст — ничего);
- ядро после `handle_exit` (до постановки в cooldown) исполняет строку
  через `/bin/sh -c` с env `AGRY_UNIT`, `AGRY_EXIT_CODE`, `AGRY_BY_SIGNAL`;
- событие журнала `finish` с кодом выхода хука — ничего не происходит
  молча (Ст. 6); сбой хука не влияет на лестницу перезапуска;
- хук — часть попытки: группу не режем, таймаут хука — константа с именем
  (Ст. 11), упор — loud-событие.

## Типовое применение (ферма агентов)

`finish = rm -rf /tmp/$AGRY_UNIT-worktree` — каждый новый заход агента
начинается в чистом рабочем пространстве, а не в завалах прошлой жизни.

## Граница

- Потолок Ст. 1: текущие 654/656 → целиться в ≈680; Поправка №5 одним
  атомом (код + статья + проверка, Ст. 16).
- Хук не может перезапустить юнит и не может блокировать смерть.

## Приёмки

1. `make clean && make 2>&1 | grep -i warning` → пусто.
2. Демо: crashy-юнит с `finish = echo ... >> файл` — хук стреляет после
   каждой смерти, в журнале `finish` по каждой; сироты 0.
3. `make audit` → OK (аудитор знает `finish` и сверяет с числом exit'ов).
4. Слепая зона предыдущих витков (завалы /tmp) закрыта демо-транскриптом.
