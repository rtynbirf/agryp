# Тикет 007 · Namespace-клетка попыток: pid/mount рядом с cgroup

Роль: ЯДРО + ДОКТОР (контракт — AGENTS.md §3). Статус: open. Виток: 7.
Приоритет: средний. Зависит от: ничего (Ст. 15 уже держит cgroup-ветку).

## Задача

Клетка памяти (Ст. 15) ограничивает байты, но не видимость: агент видит
всю машину и всех соседей по PID-пространству. Виток 7 добавляет вторую
стену:

- ключ `.agent`: `ns = pid,mount` (пусто = без клетки — как `mem-max-mb`);
- ребёнок до exec: `unshare(CLONE_NEWPID | CLONE_NEWNS)` — попытка живёт
  в собственном PID-пространстве, соседи и их процессы не видны;
- среда не даёт unshare (нет CAP_SYS_ADMIN) — loud `ns-skip` с errno
  и работа дальше: молчаливой усечки нет (та же этика, что у
  `cgroup-skip`, Ст. 15);
- группа попытки (Ст. 9) остаётся единственным контуром казни — сигналы
  ходят через границы namespace без исключений;
- журнал: событие `ns` c перечнем включённых пространств или `ns-skip`.

## Граница

- Потолок Ст. 1: сейчас 830/832 — запас 2 строки; Поправка №8 одним
  атомом (код + статья + проверка, Ст. 16) с честной ценой.
- Никаких сетевых namespace в этом тикете: сеть — отдельный договор,
  ломает `AGRY_TOKEN_REPORT`-файл (Ст. 14) только на вид.

## Приёмки

1. `make clean && make 2>&1 | grep -i warning` → пусто.
2. Демо: юнит с `ns = pid` печатает `ls /proc | wc -l` на порядок меньше
   соседа без клетки; в журнале `ns` с пространствами.
3. `make audit` → OK (`ns`/`ns-skip` в VALID_EVENTS); сироты 0.
4. В песочнице без CAP_SYS_ADMIN — `ns-skip` с errno, супервизор живёт.
