# ЦУ 011 · Jail-приёмка на способном хосте: сироты 0 за клеткой

Роль: ЯДРО + АУДИТОР (контракт — AGENTS.md §3). Статус: done (отчёт
ниже). Виток: 9. Источник: бенчмарк витка 8, находка M7
(`docs/BENCHMARK-8.md`). Исполнено автором лично; среда ответила
открытием — «способный хост» собран на месте userns-обёрткой, ядро
agryp не менялось ни на строку. Полный отчёт витка —
`docs/spec/TZ-9.md` §2.

## Задача

Бенчмарк поймал границу Ст. 9 живьём: PDEATHSIG защищает прямого
ребёнка; агент, породивший собственных детей, оставляет их сиротами
при kill -9 супервизора (20 из 20 в песочнице). Дом-ответ уже
built-in (виток 7): `jail = pid` — ребёнок супервизора есть PID 1
pid-комнаты, а смерть init комнаты убивает комнату целиком
(pid_namespaces(7)). Песочница даёт EPERM на `clone(CLONE_NEWPID)` —
приёмка переносится на хост с CAP_SYS_ADMIN:

1. ферма 20 юнитов с `jail = pid` и вложенным агентом
   (`exec = /bin/sh -c 'while :; do sleep 1; done'`);
2. `kill -9` супервизора → через 5 с сирот 0 (комнаты умерли вместе
   со своими init);
3. тот же прогон без клетки → сироты = 20 (контроль границы);
4. аудит журнала: `jail` в спавнах, сироты 0 — `make audit` OK.

## Отчёт (виток 9, 2026-11-07)

**Ключевое открытие витка**: песочница не дала CAP_SYS_ADMIN, но дала
userns — обёртка `unshare --user --map-root-user --pid` делает супервизор
носителем CAP_SYS_ADMIN собственной user-комнаты, и штатный
`clone(CLONE_NEWPID)` (код витка 7, 877 строк) проходит как есть.
user-ns по-прежнему не трогает agryp — его трогает среда; решение
витка 7 не нарушено. Ограничение названо честно: `--mount-proc` в
песочнице EPERM (seccomp на mount(2)) — обёртка без свежего /proc,
счёты ведёт хост (он видит все комнаты снаружи).

Прогон `demo/run_demo_jail_host.sh` (цели `demo-jail-host` /
`audit-jail-host` в Makefile), сырые числа —
`demo/jail-host-transcript.jsonl`:

- проба среды в транскрипте (Ст. 6): pidns_plain EPERM, обёртка ok;
- контроль границы (20 юнитов без клетки): 40 процессов «while :» →
  kill -9 → **20 сирот из 20** (по вечному внутреннему sh на юнит —
  двойное `sh -c`-гнездо; механика M7 воспроизведена);
- лечение (20 юнитов `jail = pid` в обёртке): 20 спавнов, все
  `"jailed":1`, ноль `jail-skip` → kill -9 → **0 сирот из 20** —
  комнаты умерли вместе со своими init;
- хост после прогона чист (0 процессов).

Аудитор `demo/audit_jail_host.py` — OK: ловит недосчёт сирот,
молчаливую усечку клетки (`jailed` не при всех спавнах), `jail-skip`
в лечении, чужие юниты и две правды (клеточные поля у контроля).
