## 3. Веб-сверка учителей — свежий независимый заход (2026-11-10)

Оба исполнения ссылаются на один список учителей. Проверка через веб 2026-11-10
(независимо от обеих сессий) подтверждает список и добавляет оттенки:

- **s6-supervise** (skarnet.org): `./run` умер → супервизор порождает `./finish`,
  если тот есть, → потом `./run` снова; финиш должен быть короткоживущим.
  Передача итогов попытки: у s6-оверлея код выхода и сигнал приходят финишу
  **аргументами** (`./finish 111 0`).
  https://skarnet.org/software/s6/s6-supervise.html
- **s6 `timeout-finish`**: потолок жизни финиша — файл **в каталоге службы**,
  то есть настройка per-service (пример службы, где финиш дольше дефолта,
  требует `timeout-finish`).
  https://wiki.gentoo.org/wiki/User:Flexibeast/drafts/S6/examples
- **systemd `ExecStopPost`**: итоги попытки приходят **переменными окружения**
  (`$SERVICE_RESULT`, `$EXIT_CODE`, `$EXIT_STATUS`).
  https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html
- **systemd reload**: канонический паттерн `ExecReload=/bin/kill -HUP $MAINPID`;
  зрелая форма — `Type=notify-reload`: служба после перечитывания обязана
  сказать `READY=1`, и до этого reload не считается завершённым.
  https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/using_systemd_unit_files_to_customize_and_optimize_your_system/assembly_working-with-systemd_unit_files_working-with-systemd
- **Graceful stop, дефолты мира**: Docker — 10 c SIGTERM→SIGKILL
  (https://www.suse.com/blog/observability-sigkill-vs-sigterm-a-developers-guide-to-process-termination);
  ECS — 30 c (https://aws.amazon.com/blogs/containers/graceful-shutdowns-with-ecs/).

Вывод: нового учителя с 11-06 мир не завёз; оба исполнения держат канон.
Оттенок, который оба упустили в коде: s6 передаёт итоги попытки argv,
systemd — env; оба исполнения взяли env-шлюз (systemd-школа) — и это
согласуется со Ст. 4 («строка sh, а не плагин»): env читается любым `sh`.

## 4. Вердикты

**4.1 Потолок финиша: ни 2000, ни 5000 глобально — канон.** Мировая практика —
per-service настройка при щедром дефолте (s6 `timeout-finish`; systemd
`TimeoutStopSec` измеряется минутами, Docker 10 c, ECS 30 c). Жёсткие 2000 (Б)
режут честных уборщиков; жёсткие 5000 (А) не дают ужать торопливым. Канон для
agryp: ключ юнита `finish-timeout-ms` (0 → дефолт ядра), дефолт ядра — 5000.

**4.2 Философия поправок.** А вписывает новые правила в существующие статьи с
явным тегом поправки в тексте — конституция не толстеет. Б заводит новые
статьи — дифф истории честнее (новый инвариант = новая статья), но Ст. 17–18
при размножении витков разбегутся с нумерацией. Для reload-эпохи, где правила
доращиваются мелкими приращениями, канон — стиль А; стиль Б оправдан, когда
появляется новый инвариант, а не уточнение старого.

**4.3 Форма исполнения.** Пять атомов А дали бисектабельную историю, живые
отчёты в `tasks/done/` и приёмку по фичам; один коммит Б дал один нарратив, но
лишил историю ступеней. Для `main` канон — атомы (витки 7–10 это подтвердили).
Вилка своей формой подтверждает ту же истину с другой стороны: один коммит
годится для стенда, не для main.

## 5. Живые находки сверки (репро Б, 2026-11-10)

- **5.1 Полное `make demo-v6` — зелёное.** `OK: 37 событий журнала + 30 строк
  агентов, 5 юнит(ов), журнал не лжёт`; reload 2/1/1 без кровопролития
  (resident жив на attempt 1 с бюджетом 90), stubborn (`trap '' TERM`) добит
  ctl-kill по сигналу 9, sweeper: 3 смерти / 3 уборки, сирот 0. Репро
  воспроизводится на чистой машине.
- **5.2 Аудитор умеет фабриковать данные — найден на репро.** `make audit-v6`
  без предварительного `demo-v6` краснеет с обвинениями по конфигу, которого
  не существует («ступень лестницы… по конфигу 1000», «юнит без finish-конфига»):
  каталог `demo/v6-units/` генерируется демо на лету и в git не хранится
  (`.gitignore`), а аудитор при отсутствии данных молча подставил дефолты и
  обвинил журнал по выдумке. Это нарушение Ст. 6 самим проверяльщиком.
  Урок двойной: (а) аудитор обязан fail-closed кричать «нет каталога юнитов»,
  а не сочинять дефолт; (б) нужна негативная проба «аудитор против выдумки» —
  проверяльщик проверяльщика, как `negative_ctl_test` для ctl.
- **5.3 Двоичный `agryp` лежит в git** в обеих линиях истории. Для репо, где
  Ст. 2 требует нуля зависимостей, а Ст. 1 — одного файла C, коммиченный
  бинарник — шум в диффах; сборка воспроизводима одной командой. Кандидат в
  `.gitignore` следующей гигиенической волны (решение Хозяина).

## 6. Предложения следующему витку (дверь открыта, Хозяин решает)

1. **`finish-timeout-ms` per-unit** (школа s6 `timeout-finish`): ключ юнита,
   0 → дефолт ядра 5000. Сводит спор 2000/5000 к настройке и закрывает
   единственный спорный константный след вилки.
2. **`reload-done` ack** (школа `Type=notify-reload`): после SIGHUP-перечитывания
   — событие `reload-done` с числами; журнал получает пару `reload`→`reload-done`,
   аудитор получает право требовать закрытости скобки.
3. **Readiness-протокол файл-как-API** (это то, чего нет ни у кого): агент
   объявляет готовность созданием файла готовности (путь агенту выдаёт env
   `AGRY_READY_PATH` — рядом с `AGRY_TOKEN_REPORT`); супервизор даёт событие
   `ready`, в статусе — `ready_ms` от старта попытки. `sd_notify` без сокетов,
   s6 `notification-fd` без пайпов: готовность через файл-договор, как всё
   в этом доме. Ниша свободна — подтверждено сверкой §3.
4. **Аудитор против выдумки** (из 5.2): fail-closed на отсутствующие данные +
   негативная проба, где аудитору скармливают транскрипт без каталога юнитов и
   требуют красного с честной причиной.
