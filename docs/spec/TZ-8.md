## 1. Цель

Не маркетинг, а транскрипт: одинаковая ферма, одинаковые испытания,
числа в JSONL и в человекочитаемой таблице. Что агрюпово — названо,
что не мерилось — названо (Ст. 11).

## 2. Протокол (одинаковый для всех участников)

Общий агент — тихий и одинаковый: `/bin/sh -c 'while :; do sleep 1; done'`
(≈2 МБ RSS, ноль CPU, ноль stdout). Ферма: **100 агентов**.

| # | Метрика | Метод |
|---|---|---|
| M1 | Бинарь | размер файла + `ldd` (зависимости) |
| M2 | RSS супервизора, 0 агентов | `/proc/PID/status:VmRSS` ×3, медиана |
| M3 | RSS супервизора, 100 агентов | 5 с на разгон → VmRSS ×3, медиана |
| M4 | Журнал за 30 с | байты событий при тихой ферме за ровно 30 с |
| M5 | Сироты после kill -9 | kill -9 **только** супервизора; через 5 с считаем живых агентов |
| M6 | Рестарт одного агента | kill -9 одного агента → вернулся ли за 10 с |

Замеры записываются в JSONL-транскрипт (сырые числа, без округлений
вверх), сводка — в `docs/BENCHMARK-8.md`.

## 3. Участники и границы

- **agryp** — все метрики. Ожидания по конституции: M5 = 0 сирот
  (Ст. 9: PDEATHSIG + группы), M6 = возврат по Ст. 8.
- **stdiobus v2.0.3** — M1–M6 как есть: роутер-гибрид со спавном пулов;
  рестарт — в пределах `max_restarts`; что он не делает (бюджеты,
  самоверифицируемый журнал, ctl-файлы) — не меряем, а называем.
- **zeptopm** — N/A по всем метрикам (п. 0.2); их README-числа
  (бинарь ~11 МБ, «~7 MB per agent», «500+ agents on 4 GB RAM»)
  цитируются как претензии автора, не как наши замеры.

## 4. Поправка №9 (Ст. 16)

`MAX_UNITS 64 → 128`: код (`src/agryp.c`) + Ст. 11 (число в тексте
конституции) + проверка (grep) + регрессия (сборка без warning,
`make audit`, все демо витков 1–7 зелёные, сироты 0). Причина: ферма
агентов 100+ — реальный сценарий ниши (openhuman: «500 агентов на
$10 VPS»), 64 — наследие витка 1.
