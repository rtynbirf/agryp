## Тикет 015 — finish-timeout-ms per-unit (Поправка №13)

- Ключ юнита `finish-timeout-ms`: потолок жизни finish-хука по-взрослому,
  школа s6 `timeout-finish` (у s6 это файл в servicedir; здесь — ключ
  договора). Дефолт ядра — `FINISH_MS` 5000, что ровно дефолт s6.
- 0 и минус — НЕ «без лимита» (канон бюджетов Ст. 7 сюда не переносится):
  бесконечный хук нарушает Ст. 11, поэтому 0/минус возвращает дефолт.
  Объявлено в Ст. 11, README и здесь — молчаливой усечки нет.
- Событие упора несёт свой потолок: `"finish"` с `"timeout":true,"ms":N`.
- reload применяет ключ к живому юниту (изменение — `changed`).
- Приёмка: `make demo-finish` — slowfin (хук `sleep 2`) с
  `finish-timeout-ms = 600` добит ×4, аудитор держит 1:1 хуков со
  смертями; батарея зелёная.

## Тикет 016 — readiness файл-как-API (Поправка №14)

- Договор: каждая попытка получает env `AGRY_READY_PATH`
  (`<dir>/<unit>.ready`); агент, ставший готовым, создаёт файл;
  супервизор даёт событие `ready` с задержкой от старта попытки.
- Сокета нет, пайпа нет — файловая система и есть API (Ст. 13).
  sd_notify говорит сокетом, s6 — notification-fd; файл — ниша, которой
  нет ни у кого (сверка учителей 2026-11-10, §V TEACHERS).
- Чистота между жизнями: ready-файл снимает супервизор при смерти
  попытки и при новом спавне — чужой/старый файл попытку не переживает.
- Срез семьи несёт `"ready"`/`"ready_ms"`; статус-снимок демо показывает
  `"ready":1` у объявившегося и `"ready":0` у молчуна.
- Молчун не готов — и это факт, а не нарушение: готовность объявляется,
  а не додумывается. Принуждение к готовности (ready-бюджет) — дверь
  следующего витка, здесь честно не делано.
- Приёмка: `make demo-ready` (quickready объявился за 501 мс, neverready
  0 ready, сирот 0, ready-файлов не осталось) + правило №10 аудитора:
  ready — один на попытку, только у живой попытки, ms сходится с
  расстоянием spawn→ready (±2 мс — такт now_ms).

## Продолжение витка 11 · тикет 017 (2026-11-10, Поправка №15)

- Скобка `reload`→`reload-done` (предложение 2 сверки): reload несёт
  `added`/`changed`/`removed`/`skipped`/`gen`; reload-done закрывает,
  когда все удалённые попытки мертвы, с теми же числами, gen и честным
  `ms` оседания. Второй SIGHUP скобку не перекрывает.
- `reload-kill` (школа ctl-kill): удалённый, игнорирующий TERM
  GRACE_MS, казнится законом — скобка обязана закрываться всегда;
  shutdown закрывает скобку вслух (`closed:shutdown`).
- Урок stubborn-демо: смерть попытки добивает её группу SIGKILL —
  упрямец второго слоя (`sh script` плодит dash без trap'а) больше не
  переживает попытку (Ст. 4 доведена до конца).
- Аудитор: правила №11–№12 (закрытость скобки, сходимость окон,
  kill→труп для reload-kill).
- Приёмка: `make demo-reload` — reload 1/1/2 gen=1, stubborn добит,
  reload-done ms ≥ 3000, сирот 0; батарея rc=0; санитайзеры чисто;
  ядро 1320/1330.
