## 1. Задачи витка (постановка учителя)

- **Т1. ЯДРО — finish-хук** (тикет 004): ключ `finish = <строка sh>`;
  после КАЖДОЙ смерти попытки, до лестницы; env `AGRY_UNIT`,
  `AGRY_EXIT_CODE`, `AGRY_BY_SIGNAL`; вне группы попытки; `FINISH_MS`
  — константа (Ст. 11); упор — loud; сбой хука лестницу не трогает.
  Поправка №5 одним атомом.
- **Т2. ЯДРО — эскалация ctl-stop** (тикет 006): `ctl_since_ms`;
  TERM не убил за `GRACE_MS` → `ctl-kill` + SIGKILL группы; казнь
  законом (`sup_kill`), повтор казни исключён; `ctl-drop` дедуплицирован
  реестром последних 8 имён. Поправка №6 одним атомом.
- **Т3. ЯДРО — SIGHUP-reload** (тикет 005): каталог `*.agent`
  перечитывается без смерти детей; changed — ключи сразу (дедлайн
  бюджета от живой попытки), added — юнит стартует (с комнаткой cgroup),
  removed — graceful-stop по Ст. 9; события `reload` (числа),
  `unit-added`, `unit-removed`. Поправка №7 одним атомом.
- **Т4. АУДИТОР**: словарь +6 событий; дисциплины — finish 1:1 со
  смертями и после exit; ctl-kill без exit — ложь; спавн после
  unit-removed невозможен; числа `reload` сходятся с юнит-событиями;
  отрицательный тест расширен подделкой C.
- **Т5. РАЗВЕДЧИК** (тикет 003): рефрез живой сверки §V срезом витка 6
  (тот же набор запросов, числа с живого API, токен вне печати).
- **Т6. ДОКТОР**: README, ROADMAP, ЦУ коллегам 007–009, тикеты
  003–006 → done с отчётами.

## 2. Учителя и отвергнутые пути

- Учитель Т1 — s6 `./finish` + `timeout-finish`: уборка между смертью
  и рестартом. Отвергнут exit 125 = перманентный фейл: у нас fuse —
  `CRASH_LIMIT` своих смертей (Ст. 8), хук на неё не влияет.
- Учитель Т2 — systemd `TimeoutStopSec`: TERM → пауза → KILL.
  Отвергнут пер-юнит таймаут-ключ: `GRACE_MS` — общий констант-бюджет
  прощания (Ст. 11); юнит держим 4–8 строк (Ст. 10).
- Учитель Т3 — systemd `daemon-reload`: конфиг меняется без
  кровопролития. Отвергнут hot-reload exec (zeptopm): живая попытка
  исполняет старый договор до конца — exec новой версии без смерти
  это подмена попытки; у нас изменения применяются к следующей
  попытке/дедлайну, жизни — только agrypctl.

## 5. Слепые зоны

- **Двойной dash** (`exec = sh script.sh`): попытка — внешний `sh -c`
  (лидер группы), trap юнита живёт во внутреннем dash; TERM-казнь
  убивает лидера, внутренний выживает до подбора subreaper'ом.
  Мораль: trap — в лидере (`exec = . script.sh`). Найдено демо, не
  текстом; контракт Ст. 4 (`sh -c`) не нарушен, но юнит-авторы должны
  знать. Закреплено комментарием в `demo/stubborn_worker.sh`.
- **Зомби-супервизор**: падение демо-скрипта до `kill $SUP` оставило
  живой agryp на том же каталоге — два писателя переплели события в
  одну ложь (двойные ctl-down/ctl-up в транскрипте). Фикс: зачистка
  стреев в начале демо-скриптов. Для боевого запуска: один супервизор
  на каталог — за этим следит оператор, не ядро (файл-статус не лок).
- .down для ещё не существующего юнита: ctl-drop, затем spawn и
  немедленная заморозка — громко, но двушагово.
- Retired-юниты остаются в таблице до смерти процесса (сводка честна,
  слоты MAX_UNITS не освобождаются) — мерять цену на ферме (виток 8).
- Кавыченные фразовые запросы GitHub на срезе витка 6 дали 0 (было
  135/6/1/2) — аномалия зафиксирована в §V; выводы не менялись.
